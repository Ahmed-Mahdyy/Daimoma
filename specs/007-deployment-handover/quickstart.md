# Validation Guide: Delivery

Available now: `python3 .devin/scripts/specs.py check` validates planning files, not infrastructure. Release verification requires approved provider/data/operational policies, implemented application, phase 006 acceptance, and specific deployment authorization.

## Happy Path

Build the locked candidate, deploy/migrate approved staging, run real role flows, obtain release approval, promote, then verify external HTTPS Employee/Manager/HR journeys. Follow fresh setup/test/deployment instructions as a separate reviewer. Rehearse the product/brand/architecture/Spec Kit/AI live story using real synthetic workflows.

## Edge Cases

Missing secret/host configuration, API path swallowed by SPA fallback, migration/readiness failure, unavailable email/storage/scanner, expired demo access, seed rerun, provider outage, incompatible rollback, missing private files, and failed restore. Verify failure stops promotion; never reset production to recover a schema mismatch.

## Permission and Recovery Tests

Check public application but private database/storage, role and direct-file access, CSRF/session cookies, secret-free assets/logs, restricted operational credentials, and guarded seed behavior. Restore database and attachments only into approved isolated infrastructure; compare integrity and role access, record actual recovery objectives achieved/missed.

## Evidence

Retain release identity, migration output, redacted health/security/role smoke results, restore proof, handover reproduction, secure credential-delivery record without values, AI review, rubric mapping, stage feedback and rehearsal outcomes. Missing tests remain missing; no actual URL, restore, deployment, or user credential is claimed by these files.
