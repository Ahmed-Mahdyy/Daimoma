# Validation Guide: Release Hardening

Available now: `python3 .devin/scripts/specs.py check` validates artifacts only. Domain verification requires the implemented integrated system, safe staging, approved decisions, and synthetic data.

## Happy Path

Run all backend/frontend/schema/build checks; complete employee request and time flows through manager/HR review; reproduce known expected report totals; trace results to requirements and candidate identity.

## Edge Cases

Execute time/DST/concurrency/upgrade cases, network and session faults, empty/oversize reports, unavailable storage/scanner/email, and accessibility/responsive journeys. Reproduce defects, add regression tests, correct causes, and rerun affected/full suites.

## Permission Tests

Exercise every scope boundary through direct APIs, related choices, aggregates, files, exports, notifications, and write paths. Include self-approval, former manager, inactive user, forged role/owner/status, CSRF, and privileged administrative actions.

## Performance and Evidence

Use only the approved nonproduction workload and toolchain. Record dataset, hardware, concurrency, method, latency/error/query/bundle metrics and actual output. Separate browser lab proxies from field metrics. Preserve failed/unrun outcomes and AI review corrections. Do not approve release with unresolved blocking findings or substitute these instructions for execution evidence.
